Quant Trading System · Design Notes

04 · 设计规范

单一真相源、核心契约、管线、执行语义、配置/时间/金额与 DoD。

本文是系统的规范宪法。使用 必须（MUST）、应该（SHOULD）、可以（MAY） 表达约束强度。结构描述见 architecture.md；本文定义语义、契约、 所有权和执行规则。

1. 状态与修改

  • 本文是 normative；任何违反本文的实现都是缺陷。
  • 修改本文必须走 ADR 流程，除非只是修正错别字/链接。
  • 已接受的 ADR 优先于本文；本文必须链接对应 ADR。
  • 本文与代码冲突时，按 README.md 的裁决规则处理。

2. 不变量

以下不变量是硬约束，任何一层都不得违反：

  1. 账本唯一：现金、持仓、成本、可卖数量、已实现盈亏只能由 execution/AccountLedger 写入。
  2. 策略纯 alpha：策略不得持有现金/持仓账本，不得直接发订单或改成交。
  3. 单一所有者：每个可变数据体只有一个 writer；其他层只读快照。
  4. 单向依赖：依赖只能从编排/适配器指向 domain/，不能反向或横向。
  5. 禁止同 bar 收盘成交：D 日收盘决策最早 D+1 开盘成交。
  6. 费用唯一源：所有费用/税计算必须走 cost.TransactionCost；费率来自 config/fee_config.yaml。
  7. 时间注入：所有业务时间来自 Clock；除 live 适配器边界外禁止 datetime.now()。
  8. 配置显式：阈值、路径、费率、token 不得硬编码；secret 不得进入 tracked YAML。
  9. 确定性：回测不得有未播种随机、网络 I/O 或隐藏全局状态。
  10. 文档同步：契约/行为变化必须在同一改动中更新本文、ADR 和测试。

3. 分层与依赖

完整矩阵见 architecture.md。摘要：

  • domain/：纯值对象/端口，无 I/O、无 pandas。
  • strategy/：只依赖 domain/ 和自己的 indicators/factors。
  • portfolio/、risk/：只依赖 domain/，是策略/决策，不是状态存储。
  • execution/：依赖 domain/ + cost/；拥有订单和账本。
  • datafeeder/：实现 DataPortal；不依赖策略/执行。
  • backtest/、live/：composition roots。
  • visualization/：只读快照。
  • patterns/：研究沙箱，禁止被生产路径 import。

4. 单一真相源

每个可变数据体只有一个权威 writer。派生视图可以有很多，但必须只读、可重建。

数据体 唯一 owner / writer 读者 禁止
Instrument：lot/tick/currency/price limit/calendar datafeeder execution、strategy、risk 策略里写死市场规则
Bars/quotes/provenance/quality flags datafeeder DataPortal 消费者 策略直接抓数据
DataPortal 只读视图 datafeeder.portal strategy/backtest/live/visualization 消费者修改
Config 与 secrets config/ loader 所有层通过显式 config 对象 硬编码阈值；secret 进 tracked YAML
费用/税公式 cost.TransactionCost execution/backtest 重复费用数学
Alpha/Intent/ExitPlan strategy/ execution/risk/sizing 策略改现金/持仓
Sizing policy portfolio/ execution/backtest portfolio/ 存持仓
Risk limits/decisions risk/ execution/backtest risk/ 拥有现金/持仓
Order 生命周期 execution/OrderManager strategy 只读、visualization 策略/engine 直接改订单状态
Fills execution/BrokerPort ledger/strategy/analytics 伪造 fill
现金/持仓/成本/可卖数量/已实现 PnL/FX execution/AccountLedger 所有层通过 AccountSnapshot engine/strategy/PM/RM 各存一份
Account snapshot execution/AccountLedger strategy/risk/visualization 暴露可变快照
绩效指标 backtest/performance / reporting 报表/可视化 把指标当账本真相
策略私有状态 strategy/ 无 策略对象跨策略共享
可视化状态 visualization/ UI 回写执行/策略

规则：

  • 一个 writer：表中 owner 是唯一写入者；其他层只能读快照或发指令。
  • 派生不是重复：多个报表/快照是允许的，但必须从权威状态计算，不能独立维护。
  • 适配器不是重复：多个数据源/broker 实现同一个端口，是兼容性，不是重复真相。

5. 核心契约

契约定义在 domain/，字段和语义如下。具体 Python 类型在实现时确定；这里锁定概念。

5.1 Instrument

必须包含：symbol、market、currency、lot_size、tick_size、price_limit_rule、 trading_calendar、board（主板/创业板/科创板/ST 等，若可得）。

用途：执行层决定 lot/tick/涨跌停；策略不得写死这些规则。

5.2 DataPortal

只读行情访问。必须支持：

  • history(symbols, start, end, fields)：PIT 历史 bars；
  • latest(symbols, as_of)：截至 as_of 的最新 bar/quote；
  • calendar(market)：交易日；
  • instrument(symbol)：静态元数据。

必须明确复权口径（raw/adjusted）和 bar 时间戳语义（bar open vs bar close）。禁止在 策略内部直接访问数据库/网络。

5.3 Strategy

on_start(ctx)
on_bar(ctx) -> Iterable[Intent]
on_fill(fill)
on_end()
  • 必须只读 StrategyContext；不得持有现金/持仓账本。
  • 必须无副作用地生成 Intent；不得直接调用 broker/数据源。
  • 策略私有状态可以保存在策略对象内，但不得跨策略共享。
  • 必须确定性；不得使用未注入的时间/随机数。

5.4 StrategyContext

只读视图，至少包含：now、account（AccountSnapshot）、positions、 open_orders、data（DataPortal 只读接口）、params。

不得暴露可变 Position 对象或 engine 内部字典。

5.5 Intent

策略意图，不是可执行订单。字段：

  • symbol、side（BUY/SELL）；
  • qty 或 target_position（二选一）；
  • order_type：MARKET/LIMIT/STOP/STOP_LIMIT；
  • limit_price、stop_price；
  • tif（DAY/GTC/IOC，按需要）；
  • exit_plan（可选，见 5.6）；
  • reason、client_id、tag。

Intent 必须能被风控/定仓层拒绝或调整；它不是最终订单。

5.6 ExitPlan

入场时声明，至少包含：

  • initial_stop：初始止损价；
  • risk_per_share = entry_fill - initial_stop（R）；
  • targets / partials：目标价与卖出比例；
  • trail：激活 R、ATR 倍数或结构规则（策略计算，执行层只认 stop price）；
  • time_exit_days：可选时间退出；
  • breakeven_after_r：可选保本激活。

不变量：

  • stop_price 只能上移，不能下移；
  • R 在入场时锁定，之后不变；
  • 部分卖出只减少 shares，不改变 R 分母；
  • 多头 initial_stop < entry_fill。

执行层不认识 ATR；策略把 ATR 规则换算成具体 stop_price，执行层只执行订单。

5.7 Order

执行层接受的指令。必须包含：order_id、symbol、side、order_type、qty、 limit_price/stop_price、status、filled_qty、avg_fill_price、created_at、 updated_at、reject_reason。

订单状态机至少：NEW → SUBMITTED → PARTIALLY_FILLED → FILLED，以及 REJECTED、 CANCELLED、EXPIRED。状态只能由 execution/OrderManager 修改。

5.8 Fill

成交事实。必须包含：fill_id、order_id、symbol、side、price、qty、 fees（commission/stamp/other）、timestamp、liquidity_flag。

Fill 由 broker 产生，由 ledger 应用；策略只能读。

5.9 AccountSnapshot

不可变只读快照。必须包含：cash_total、cash_available、positions（每项含 symbol、qty、sellable_qty、avg_cost、realized_pnl）、equity、 unrealized_pnl、currency、as_of。

Position 是 snapshot 的条目，不是策略共享的可变对象。

5.10 BrokerPort

submit(order) -> order_id
cancel(order_id)
query(order_id) / open_orders()

由 SimulatedBroker 和 LiveBroker 实现。只有 broker/ledger 能改账户；策略和 engine 不得直接改。

5.11 RiskPolicy

evaluate(intent, snapshot) -> allow | reject(reason) | resize(qty)

必须是纯决策，不修改账户。风控状态（熔断、连续亏损计数）由 risk/ 拥有，但不得 复制现金/持仓账本。

5.12 Clock

SimClock（回测）/ RealClock（paper/live）。所有业务时间必须来自 Clock； datetime.now() 只允许出现在 live 适配器边界。

6. 管线契约

DataPortal + Clock
  -> Runner -> Strategy.on_bar(ctx) -> [Intent]
  -> RiskPolicy.evaluate -> SizingPolicy
  -> ExecutionEngine/OrderManager -> Broker(Sim/Live) -> [Fill]
  -> AccountLedger.apply(fill) -> AccountSnapshot
  -> Strategy.on_fill + observability + visualization
  • backtest = historical DataPortal + SimClock + SimulatedBroker。
  • paper = live DataPortal + RealClock + SimulatedBroker。
  • live = live DataPortal + RealClock + LiveBroker。
  • visualization = 订阅 Fill/AccountSnapshot/Order 事件，只读。

四者必须共用 Strategy、SizingPolicy、RiskPolicy、AccountLedger。只替换 数据/时钟/broker 适配器。不得为 live 另写一套策略/账本逻辑。

7. 执行语义

维度 规则
决策时点 收盘 D 产生意图，最早 D+1 开盘执行；禁止同 bar 收盘成交
订单类型 MARKET/LIMIT/STOP/STOP_LIMIT；止盈/移动止损由策略换算成 STOP 或条件单；执行层不认识 ATR
盘中触发 卖出止损：low <= stop → 成交价 min(open, stop)；止盈：high >= target → max(open, target)；跳空按开盘
同日双触发 同一 bar 同时触止损和止盈时，默认止损优先（保守）；必须记录 tie-break 规则
A 股 T+1 D 日买入的 shares 在 D+1 才可卖；ledger 维护 sellable_qty
涨跌停 开盘即封板且方向不利 → 不成交；顺延/过期策略必须显式；连续 N bar 未成交 → forced_exit 并打标
停牌 无成交；订单保留或过期按显式策略；不得静默跳过
lot/tick 使用 Instrument；A 股 100 股整手；港股 board lot；价格按 tick 舍入
费用 每笔 fill 走 cost.TransactionCost；最低佣金、卖出印花税、港股印花税取整；费用明细写入 Fill
滑点 显式模型/配置，不藏在信号价里；回测默认值必须在报告中披露
部分成交 回测用确定性 participation/volume cap；live 用真实 broker fill
部分退出 Intent.qty 或 ExitPlan.partials；R 分母不变；每笔费用独立
企业行为 执行用可交易 raw price；分析可用 adjusted；复权因子必须 PIT，禁止 look-ahead
分红/红利税 ledger 记录现金和税基；持有期决定税率；未实现则必须显式声明不支持
拒单 拒单是显式记录（reason），不是静默 return
确定性 回测无 datetime.now()、无未播种随机、事件循环内无网络
污染数据 质量 flag 是策略输入；不可交易 bar 必须标记/审计，不能无记录丢弃

8. 策略契约

  • 策略是纯 alpha：只读 StrategyContext，只发 Intent。
  • 策略不得 import backtest/、execution/、portfolio/、risk/、datafeeder/； 只依赖 domain/、自身 indicators/factors、config/。
  • 策略不得持有现金/持仓账本，不得修改 AccountSnapshot。
  • 策略必须确定性；时间/随机数通过 context 注入。
  • 策略必须在入场时声明 ExitPlan；出场更新通过 Intent 表达，不能直接改 Position。
  • 策略可以有自己的参数和私有状态；不得跨策略共享可变对象。

9. 组合与风险契约

  • portfolio/SizingPolicy：把 Intent 转成目标数量/权重；纯函数/纯策略；不存持仓。
  • risk/RiskPolicy：检查单票/行业/总仓位、熔断、连续亏损、流动性等；返回 allow/reject/resize；不修改账本。
  • 风险状态（熔断计数、当日基准）由 risk/ 拥有；现金/持仓来自 AccountSnapshot。
  • 不得出现 engine/PM/RM 各存一份资本或现金的情况。

10. 配置、时间与金额

配置

  • 所有 tunable 必须在 config/*.yaml，通过单一 loader 读取。
  • 优先级：run override > 环境变量（secrets/运行时）> YAML > 代码默认值。
  • Secret 只在 config/tokens.yaml 或环境变量；不得进入 tracked settings.yaml。
  • 新 key 必须有 owner、unit、default、allowed range。
  • YAML 百分比字段用百分点（20.0 = 20%），领域字段用比率（0.20）；后缀必须区分 _pct 与 _ratio。

时间

  • 内部统一 timezone-aware UTC；交易所规则用 Asia/Shanghai / Asia/Hong_Kong。
  • Bar 时间戳语义必须明确（bar open 或 bar close），全系统一致。
  • 业务时间只来自 Clock；datetime.now() 只在 live 适配器边界允许。
  • 交易日是 date，不是任意 datetime。

金额

  • 账本、现金、费用、已实现 PnL 用 Decimal + 显式币种。
  • 指标/研究/分析可用 float；转换边界必须记录。
  • CNY/HKD 不得隐式相加；换汇要记录 rate/source/timestamp。
  • 价格按 tick、数量按 lot、金额按交易所规则舍入。
  • 年化口径（252 交易日）、无风险利率来源、收益口径必须在一处定义。

11. 观测、持久化与审计

  • 订单/成交/账本快照必须可持久化/回放；回测确定性 ID，live 用 UUID。
  • 日志必须结构化，包含 run_id、symbol、order_id、fill_id、reason。
  • 库代码禁止 print；CLI/研究脚本可以使用。
  • 实盘必须有审计日志、对账（broker vs ledger）、kill switch、订单幂等。

12. 测试与 Definition of Done

测试类别：

  • 单元：domain/config/cost/sizing/risk。
  • 契约：DataPortal、BrokerPort 的实现一致性。
  • 不变量：账本守恒、lot/tick、T+1、棘轮、部分卖出。
  • 黄金场景：完整管线的确定性回放。
  • 回测/实盘 parity：同一脚本在 SimulatedBroker 与 paper/live 适配器上行为一致。
  • 研究测试与生产测试分开；patterns/ 不进入默认生产测试路径。

DoD：

  • 契约/ADR 先更新。
  • 所有权表未变或已更新。
  • 单元 + 集成测试。
  • 行为变化有不变量/黄金场景测试。
  • make check 通过（lint/type/tests/import contracts/docs links）。
  • 无禁止 import 方向。
  • 无重复现金/持仓/config。
  • 无 datetime.now()/隐藏不确定性。
  • 费用只走 cost.TransactionCost。
  • 配置 key 有 owner/unit/default/range。
  • 文档更新并交叉链接。
  • 触发时链接 ADR。
  • 无 secret/过期行号引用。

13. 变更控制

必须写 ADR 的变更：

  • 分层/依赖方向；
  • 单一真相源/所有权；
  • 核心契约（Intent/Order/Fill/AccountSnapshot 等）；
  • 执行语义（成交、费用、T+1、涨跌停、部分成交）；
  • 配置 schema；
  • 参考框架；
  • 新运行时依赖。

流程：

  1. 写 ADR（Proposed）。
  2. 更新本文对应章节并链接 ADR。
  3. 改代码 + 测试。
  4. 更新 roadmap.md 阶段/偏差。
  5. ADR 置为 Accepted；永不删除，Superseded 时保留链接。

与 prereg 冲突：不得静默改写预注册；必须加 changelog 并重跑。

附录 A：不变量清单

  1. sum(position.qty * price) + cash == equity（按币种）。
  2. sellable_qty <= qty；A 股 T+1 后 sellable_qty 才增加。
  3. stop_price 非递减；initial_risk 入场后不变。
  4. 部分卖出后 qty_remaining + qty_sold == qty_initial；R 分母不变。
  5. 每笔 fill 的 amount == shares * price；费用明细可加总。
  6. 订单状态只能前进，不能回退（除显式 cancel/reject）。
  7. 回测相同输入/配置/种子 → 相同结果。

附录 B：拒绝模式

  • 策略持有/修改现金或持仓。
  • engine 直接改 PM/RM 的内部资本。
  • 同一状态在 engine/strategy/PM/RM 各存一份。
  • 同 bar 收盘成交。
  • 用固定百分比替代初始止损/棘轮（除非作为对照变体）。
  • 在策略里写死 lot/tick/涨跌停/费率。
  • 在文档里引用 engine 行号作为契约。
  • 为 live 另写一套策略/账本逻辑。
  • 先改代码后补契约。
