05 · 代码风格

Python 基线、类型、命名、导入、日志、异常与测试规则。

本文定义代码风格与工程规则。结构见 architecture.md，语义见 design_spec.md。新代码必须遵守；旧代码在迁移时逐步收敛，不得继续 扩大违规。

1. 非协商项

  1. 每个可变状态只有一个 writer。
  2. 依赖方向不能反向或横向。
  3. 策略不得持有/修改现金、持仓、订单。
  4. 费用只走 cost.TransactionCost。
  5. 时间只来自 Clock；datetime.now() 只在 live 适配器边界。
  6. 配置/secret 不硬编码。
  7. 库代码不 print；不 broad except；不吞异常。
  8. 契约/分层变更先写 ADR。

2. Python 基线

  • Python 3.10+；新文件使用 from __future__ import annotations。
  • 使用内置泛型：list[str]、dict[str, int]、tuple[...]、X | None。 新代码不用 typing.List/Dict/Optional/Union。
  • 数据模型优先 @dataclass；不可变值对象用 frozen=True。
  • 枚举用 enum.Enum / IntEnum；不要用魔法字符串。
  • 接口用 typing.Protocol；不要为每个小功能建 ABC 继承树。
  • 不使用通配导入（from x import *）。

3. 类型与数据模型

  • 公共函数/方法必须有参数和返回值类型；内部短函数也应尽量标注。
  • 避免 Any；确实需要时在注释里说明边界。
  • 值对象不可变；可变状态集中在 AccountLedger / OrderManager。
  • 不把 pandas DataFrame 当领域对象传递；在适配器/分析边界转换。
  • 金额、数量、价格使用明确类型/单位；不要用裸 float 混用币种。

4. 命名

  • 模块/函数/变量：snake_case；类：PascalCase；常量：UPPER_SNAKE_CASE。
  • 私有：前缀 _。
  • 领域术语以 glossary.md 为准；不要为同一概念造多个名字。
  • 单位后缀必须明确：_pct（百分点）、_ratio（比率）、_amount（金额）、 _price、_qty、_ts、_days。
  • 布尔变量用 is_/has_/can_ 前缀；避免 flag。
  • 不用 data、info、obj、tmp 作为公共 API 名称。

5. 模块与导入

  • 一个模块一个职责；模块名说明“它拥有什么”。
  • __all__ 只导出公共 API；内部实现不导出。
  • 禁止 wildcard import；禁止在 __init__.py 写业务逻辑。
  • 生产代码只能按 architecture.md 的方向 import。
  • patterns/、scripts/、backtest/ 不得被 strategy/、domain/ 反向 import。
  • 避免 lazy import 解决循环依赖；如果出现循环，说明分层错了，先改结构。
  • 不允许在函数内 import 生产依赖来“绕过”分层；唯一的例外是可选依赖/CLI 启动。

6. 函数与类

  • 优先纯函数；副作用留在边界（数据、执行、日志、UI）。
  • 函数只做一件事；参数过多时用 dataclass/config 对象。
  • 不用 boolean flag 参数控制行为；用 enum 或拆方法。
  • 类小、职责单一；不要 god object。
  • 组合优于继承；只有真正的 is-a 关系才用继承。
  • 公共 API 不返回可变内部状态；返回快照/副本。
  • 异常路径显式；不要用 None 表示多种失败原因。

7. 数据与 pandas

  • pandas 只用于数据适配器、研究、绩效分析；领域契约用普通值/序列。
  • 明确 copy/view：修改共享 DataFrame 前先复制。
  • 时间列必须 timezone-aware；不要混用 naive/aware。
  • 不在循环里反复 iterrows() 处理大数据；优先向量化，必要时用 itertuples。
  • 数据列名、单位、复权口径在读取时统一；不要在下游猜测。

8. 错误与日志

  • 领域异常集中在 domain/errors.py（目标）或现有 datafeeder/errors.py； 不要到处 raise ValueError。
  • 禁止无理由的 except Exception；捕获必须具体，并有恢复/记录/重新抛出。
  • 禁止 except: pass；如果确实要忽略，必须注释原因并记录 debug 日志。
  • 拒单/风控拒绝是记录值，不是静默 return。
  • 库代码用 logging.getLogger(__name__)；CLI/研究脚本可用 print。
  • 日志字段结构化：run_id、symbol、order_id、fill_id、reason。
  • 不记录 secret、完整 token、账户敏感信息。

9. 配置与密钥

  • 所有 tunable 进 config/*.yaml；代码里只允许物理常量（如 252 交易日）且必须注释。
  • Secret 只在 config/tokens.yaml 或环境变量；不得进入 tracked YAML。
  • 配置读取走单一 loader；不要在模块顶层读文件。
  • 新配置 key 必须写 owner/unit/default/range。
  • 百分比字段用 _pct（20.0）还是 _ratio（0.20）必须与字段名一致。
  • 配置校验失败要 fail fast，不要静默用默认值。

10. 测试

  • 测试文件放对应包的 tests/；命名 test_*.py；测试函数 test_*。
  • 单元测试不访问网络/真实数据库；需要时用 fixture/mock。
  • 随机测试必须固定 seed。
  • 行为变化必须有不变量/黄金场景测试；不能只测“能跑”。
  • 新增契约要有 contract test；新增执行规则要有 invariant test。
  • 研究测试（patterns/）与生产测试分开；默认 pytest 不依赖研究数据。
  • 测试名说明行为，不说明实现。

11. 注释与文档

  • 注释解释 why，不解释 what；代码本身说明 what。
  • 公共模块/类/函数用 docstring；Google 风格即可。
  • 文档正文中文；代码标识符英文；术语按 glossary。
  • 不写“临时/以后改”的注释；开 issue/roadmap。
  • 文档里不要引用 engine 行号作为契约；用文件名 + 符号名。
  • 变更契约/行为时同步更新文档。

12. 工具（后续阶段接入）

目标 make check：

ruff check .
ruff format --check .
mypy domain execution   # 逐步扩大
pytest
python scripts/check_imports.py
python scripts/check_docs.py

当前仓库还没有 ruff/mypy 配置；在接入前，至少：

  • 保持现有测试全绿；
  • 不新增 broad except/print/硬编码；
  • 不新增禁止 import；
  • 手动跑 python -m pytest -v。

13. 反模式

  • 共享可变 Position 对象给策略。
  • engine/strategy/PM/RM 各存一份现金/持仓。
  • 策略里写死 lot/tick/涨跌停/费率/日期。
  • 同 bar 收盘成交。
  • 用 datetime.now() 做业务决策。
  • 用固定百分比止损/止盈代替 ATR/结构（除非是预注册对照）。
  • 在文档里引用 engine 行号。
  • 为 live 另写一套策略/账本。
  • 大而全的 utils.py / common.py。
  • 先改代码后补契约。

14. Review checklist

  • 这个模块的 owner 是谁？是否只有一个 writer？
  • 是否违反依赖矩阵？
  • 是否复制了已有状态/规则？
  • 时间/随机/配置是否注入？
  • 费用是否走 cost？
  • 失败路径是否显式记录？
  • 是否有不变量/黄金场景测试？
  • 文档/ADR 是否同步？
  • 是否有 secret/行号/过时引用？
