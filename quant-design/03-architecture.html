Quant Trading System · Design Notes

03 · 系统架构

分层、包职责、依赖矩阵、运行时拓扑与 NautilusTrader 映射。

1. 目的与范围

本文定义系统的结构：包职责、依赖方向、运行时拓扑。它不定义具体策略、参数或 执行细节；那些在 design_spec.md 和 ADR 中。

范围：单用户，A股/港股，日线优先，long-only，约 75 万人民币，后续 paper trading、 实盘和可视化。非目标见 §12。

2. 系统上下文

数据源 (tencent/tushare/baostock/akshare/...)
        │
        ▼
   datafeeder (数据层) ──► 本地存储 (quality/market_data/provenance/...)
        │
        ▼
   strategy (alpha) ──► portfolio (sizing) ──► risk (policy)
        │                                      │
        └──────────────► execution (orders/ledger/broker)
                                 │
                                 ▼
                    backtest / paper / live / visualization

3. 设计哲学

  1. One owner：每个可变状态只有一个写入者。
  2. One direction：依赖从编排/适配器指向纯领域，不能反向或横向。
  3. One pipeline：backtest、paper、live、visualization 共用同一条事件序列； 只替换 Clock、DataPortal、Broker 适配器。
  4. Specs before code：分层、所有权、契约、执行语义、配置 schema 的变更先写 ADR/规格。
  5. Boring, explicit, deterministic：同步主循环、注入时钟、显式配置、无隐藏全局 状态；不做微服务、事件溯源、HFT。

4. 当前 vs 目标

当前代码是过渡期实现：

  • backtest/engine.py 是 composition root，同时拥有现金、持仓、撮合、 PositionManager、RiskManager。
  • strategy.positions 是 engine 持仓的共享引用；PositionManager 又存一份 PositionInfo 副本；现金在 engine/strategy/PM/RM 各有一份派生值。
  • Signal 只有 BUY/SELL/HOLD、price、metadata；SELL 永远全平。
  • 回测当根收盘成交，没有 D+1、盘中 high/low、T+1、涨跌停、部分卖出。

目标结构把状态和职责分开：

关注点 当前 目标
现金/持仓账本 engine + strategy + PM + RM execution/AccountLedger 唯一
订单/成交 engine 内联 execution/OrderManager + BrokerPort
策略输入 共享可变 Position 只读 StrategyContext
策略输出 Signal(BUY/SELL) Intent（含数量/订单类型/ExitPlan）
sizing PositionManager 兼管持仓 portfolio/SizingPolicy 纯策略
风控 RiskManager 兼管资本 risk/RiskPolicy 返回决策
回测/实盘 两套路径 同一管线，只换适配器

core/ 不要重新引入。目标纯领域包命名为 domain/，只放值对象、枚举、端口， 不包含 engine 或 pipeline。

5. 目标分层

app / main.py / scripts / visualization
        │
        ├── live/          (live adapters + runner)
        └── backtest/      (historical replay + analytics)
                 │
                 └── execution/   (orders, ledger, brokers)
                        │
        strategy/ ──────┤
        portfolio/ ─────┤
        risk/ ──────────┤
                        └── domain/  (pure contracts, no I/O)
        datafeeder/ ────┘  (implements DataPortal)
        cost/ ──────────┘  (pure fee formulas)

依赖只能向下。backtest/ 和 live/ 是 composition roots：它们负责把数据、策略、 sizing、风控、执行、账本接起来；engine 本身不拥有业务状态。

6. 包职责

包 职责 明确不负责
domain/（目标） Instrument、Bar、Intent、ExitPlan、Order、Fill、AccountSnapshot、BrokerPort、Clock 等纯契约；无 I/O、无 pandas 数据抓取、撮合、策略、报表
datafeeder/ 数据源适配器、存储、日历、质量/溯源、DataPortal 实现、PIT 查询 策略、订单、现金
cost/ 费用/税公式，费率来自 config/fee_config.yaml 订单状态、持仓
strategy/ alpha 生成、Intent/ExitPlan 声明、策略私有状态 现金/持仓、订单执行、数据抓取
portfolio/ sizing 策略（R 定仓/资金百分比）、目标仓位 持仓存储、成交
risk/ 预交易风控、暴露/集中度/熔断决策 现金/持仓账本、撮合
execution/（目标） OrderManager、AccountLedger、SimulatedBroker、LiveBroker 适配器、交易规则 策略 alpha、数据抓取
backtest/ 历史回放、绩效分析、walk-forward 生产状态所有权
live/（目标） 实盘 runner、实时数据/券商适配器 策略逻辑
visualization/（目标） 只读快照、报表、dashboard API 写回执行/策略状态
scripts/、main.py composition roots、CLI、运维脚本 领域逻辑
patterns/ 研究沙箱、实验代码 被生产路径 import

7. 依赖矩阵

包 允许 import 禁止 import
domain/ 仅标准库 任何内部包
datafeeder/ domain/、config/、自身 strategy/、backtest/、portfolio/、risk/、execution/
cost/ 标准库、config/ 其他业务包
strategy/ domain/、自身 indicators/factors、config/ backtest/、execution/、portfolio/、risk/、datafeeder/
portfolio/ domain/、config/ 持仓存储、execution/、strategy/
risk/ domain/、config/ 现金/持仓存储、execution/、strategy/
execution/ domain/、cost/、config/ strategy/、datafeeder/、backtest/
backtest/ 所有下层 + domain/ 被下层 import
live/ 所有下层 + domain/ 被下层 import
visualization/ domain/、只读快照/报表 API 写 execution//strategy/ 状态
scripts/、main.py 所有层 被库代码 import
patterns/ 任意研究依赖 被生产路径 import

测试可以组合高层；生产代码必须遵守矩阵。后续用 import-linter 或 AST 检查固化。

8. 运行时拓扑

模式 数据 时钟 Broker 备注
backtest 历史 DataPortal SimClock SimulatedBroker 确定性、可复现
paper 实时/准实时 DataPortal RealClock SimulatedBroker 与实盘同数据路径，不真发单
live 实时 DataPortal RealClock LiveBroker 需 paper 门槛、对账、kill switch
visualization 读快照/事件 — — 只读，不参与交易

四者共用 Strategy、SizingPolicy、RiskPolicy、AccountLedger。只有适配器不同。

9. 事件流

Clock
  -> DataPortal.get_bars()
  -> Strategy.on_bar(market, portfolio) -> [Intent]
  -> RiskPolicy.evaluate(intent, snapshot) -> RiskDecision
  -> SizingPolicy.size(intent, snapshot) -> OrderRequest
  -> OrderManager -> Broker.submit()
  -> [Fill]
  -> AccountLedger.apply(fill)
  -> AccountSnapshot
  -> Strategy.on_fill() + observability + visualization

不需要 message bus/actor/async。同步主循环足够；实盘适配器可以在边界做异步 I/O， 但不把异步传染到策略和账本。

10. NautilusTrader 概念映射

参考框架：NautilusTrader（见 adr/0001-nautilustrader-reference.md）。 只借概念，不引入运行时依赖。

Nautilus 概念 本项目对应 说明
DataClient / DataEngine DataPortal + datafeeder/ PIT 读取，不暴露 venue 细节
Strategy strategy/ 只发 Intent，不碰账本
ExecutionEngine / OrderManager execution/ 订单生命周期、撮合
Portfolio execution/AccountLedger 现金/持仓/已实现盈亏唯一账本
RiskEngine risk/RiskPolicy 预交易决策，不拥有资本
MessageBus / Cache 简化同步循环 + 只读快照 不采用 actor/async 运行时
Clock Clock（Sim/Real） 禁止 datetime.now()
Adapters SimulatedBroker / LiveBroker 同一 BrokerPort

不采用：actor 模型、message bus 基础设施、async 并发、多 venue 路由、Nautilus 的 instrument universe 实现、其 Rust/Cython 内部。

11. 单一真相源摘要

完整表在 design_spec.md。要点：

  • 现金/持仓/成本/可卖数量：只有 execution/AccountLedger 写。
  • 订单/成交：只有 execution/ 写。
  • 费用公式：只有 cost.TransactionCost。
  • 行情/Instrument/日历：只有 datafeeder/。
  • 策略意图：只有 strategy/。
  • 配置/密钥：只有 config/ loader。
  • 绩效/报表：backtest/performance / reporting 派生，不是账本。
  • 可视化：只读快照，不回写。

12. 可视化与实盘

  • 可视化：订阅 AccountSnapshot、Fill、Order 事件；dashboard 只读 reporting API。禁止 import engine 内部状态。
  • 实盘：LiveBroker 实现 BrokerPort；live/runner 复用同一管线。安全设施： paper 模式、kill switch、订单幂等 ID、成交对账、审计日志、人工确认、单票/总仓位硬 上限。
  • paper：实时数据 + SimulatedBroker，用于 3–6 个月验证；与 live 共用数据/策略/ 风控/账本路径。

13. Out of scope

  • 微服务、分布式消息总线、事件溯源持久化。
  • 多用户/认证/多租户会计。
  • HFT、tick 级延迟优化、做市基础设施。
  • 做空、科创板、期权、期货、美股实盘。
  • 完整采用 NautilusTrader 运行时或硬依赖。
  • 完整税务申报/券商对账系统。
  • ML 平台/feature store/自动研究编排。
  • 执行现实性与 paper 门槛通过前的盘中自动交易。

14. 已知偏差

当前代码与目标结构的差距记录在 roadmap.md。不要在文档中把目标行为 写成现状；引用当前行为时标注“过渡期”。
